# 隐私与数据说明

> 适用版本：0.1.1 发布候选版
> 本说明描述当前实现边界，不构成对尚未验收安装包的发布声明。

## 1. 本地优先原则

Assistant Product Manager 的正式业务数据以本机 SQLite 和受管应用数据目录为真值来源。应用不要求登录中央账号，也不会为了展示界面自动上传整个工作区。

浏览器预览与桌面数据隔离。浏览器 localStorage 只用于开发 UI 预览，不是正式数据源，也不会读取桌面数据库或 Windows Credential Manager。

## 2. 保存的数据

SQLite 可能保存：

- 项目、里程碑、确认事项和通知记录；
- 会议、稳定段落、需求卡及不可覆盖版本；
- 项目记忆、来源和冲突关系；
- 文档、设计 Brief、指标、分析运行、实验和洞察；
- VOC、研究、竞品、决策、风险、依赖、发布和复盘；
- Provider 的非敏感元数据，例如类型、服务地址和模型名称；
- Agent 的状态、耗时、Token、错误码、内容长度和哈希等脱敏 Trace。

会议附件保存在应用数据目录的 `attachments/meetings` 子目录。SQLite 保存受控路径、大小、类型和哈希。备份保存在应用数据目录的 `backups` 子目录，用户也可以导出到自选位置。

Windows 上的确切根目录由系统和 Tauri 根据应用标识 `com.assistant-product-manager.desktop` 解析。为了避免误删或误改，不建议依赖猜测路径；应优先使用应用内备份、导出和恢复功能。

## 3. API Key 与凭据

OpenAI、Anthropic 和 OpenAI-compatible API Key 只允许保存到 Windows Credential Manager。密钥不得进入：

- SQLite 业务表；
- localStorage；
- 普通日志、Agent Trace、备份或崩溃摘要；
- React 页面状态的持久化结果；
- Sidecar 响应和标准输出 ready 事件。

工作台只创建上述三个固定 Credential Manager 账户，不接受任意 Provider 名称。密钥必须是 1–512 字节可见 ASCII；若通过系统工具手工写入空值、空格、控制字符、不可见 Unicode 或超长值，连接测试和生成都会拒绝使用，并在设置页提供替换或删除入口。前端只接收缺失、无效、有效三态，不接收凭据正文；底层凭据存储错误正文也不会原样返回。

Tauri 仅在单次 Provider 请求前从 Credential Manager 读取密钥到内存，并通过带随机会话令牌的本机回环链路交给 Sidecar。Sidecar 只绑定 `127.0.0.1`，请求结束后不持久化密钥。

CC Switch 模式只访问 `127.0.0.1:15721` 的允许路由，不读取或复制 CC Switch 的数据库和密钥。

## 4. 外部传输

只有用户显式触发连接测试或 AI 生成时，受限输入才会发送到所配置的 Provider。可能发送的内容取决于业务动作，例如：

- 固定诊断 Agent：只发送合成样本，不读取业务数据；
- 会议需求分析：发送当前会议的受限稳定段落；
- 项目问答或审阅 Agent：发送当前项目内经过白名单选择的上下文和证据；
- 文档或数据解释：发送允许的已确认需求或确定性分析结果。

Provider 的隐私、保留和训练策略由用户选择的服务商决定。使用前应检查该服务商条款，并避免向无权处理敏感信息的模型发送内容。

研究搜索适配器只持久化非敏感配置、用户明确保存的来源引用和访问时间。启用内置中文维基百科后，用户输入的搜索词会经 Tauri 和带会话鉴权的本机 Sidecar 发送到 `zh.wikipedia.org`；相同查询及其预览结果只在 Sidecar 内存缓存 5 分钟、最多 50 项，不写入 SQLite，进程退出即清除。WebView 不直接连接远端，通用适配器端点也不得包含凭据。外部搜索尚未完成正式桌面验收，返回内容不会自动成为已确认事实。

## 5. 日志与 Agent Trace

应用只应记录运行状态和脱敏诊断信息。Agent Trace 不保存提示词正文、模型原始响应、API Key 或 Authorization Header。

故障反馈前请人工检查截图和文本。不要把会议原文、客户信息、数据库、备份或 Provider 响应直接附到公开问题中。

## 6. 备份、导出与保留

SQLite 一致性备份会包含备份时已有的业务数据和脱敏 Trace，但不包含 Windows Credential Manager 中的 API Key。受管附件不会因为只导出 SQLite 备份而自动成为独立可移植包；跨机器迁移能力必须以正式发布说明为准。

导出的 Markdown、DOCX、PDF、CSV、JSON、SVG 或备份由用户选择存放位置，离开应用受管目录后由用户负责访问控制、同步和删除。

应用不会静默删除已确认历史版本。归档通常保留记录；永久删除会议时只允许清理受管根目录内的附件，绝不根据任意数据库路径删除外部文件。

## 7. 卸载与删除

正式 v1 的卸载/保留数据策略必须经过干净 Windows 验收。在该验收完成前，应保守假设卸载程序可能保留应用数据，并在卸载前：

1. 在设置中导出一致性备份；
2. 删除不再需要的已保存 API Key；
3. 按组织要求处理导出的文档和分析文件；
4. 验证卸载后的数据库、附件和备份保留状态。

不要手工删除无法确认归属的系统目录。最终安装包会在发布验收记录中明确验证实际行为。

## 8. 安全边界与已知限制

- 当前没有通过签名与干净 Windows 验收的正式安装包。
- 云 Provider、Credential Manager 和真实业务生成仍需要安装态人工验证。
- Sidecar 失败时会降级 AI，但不能把该机制视为网络隔离或恶意软件防护。
- 搜索来源和模型建议都必须由用户审核；AI 不自动覆盖正式业务数据。
- 本产品当前面向单机个人工作区，不提供多用户访问控制或组织级密钥托管。

发现疑似凭据泄漏时，应立即撤销 Provider Key、删除 Credential Manager 中的旧值，并在分享任何诊断材料前完成脱敏。
