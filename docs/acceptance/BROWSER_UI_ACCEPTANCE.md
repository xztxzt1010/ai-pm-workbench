# P9 浏览器布局与可访问性验收记录

> 验收日期：2026-07-17  
> 验收对象：`http://127.0.0.1:1420/` 浏览器预览  
> 结论范围：浏览器渲染与 DOM 可访问性；不替代 Tauri、Windows 缩放或安装态验收。

## 1. 覆盖范围

本轮检查今日驾驶舱、项目列表、首次引导和项目工作区，使用以下 CSS 视口：

- 800×600：模拟小窗口或高缩放后的紧凑可用区域；
- 1024×640：当前 Tauri 主窗口最小尺寸；
- 1280×720：常用桌面工作区尺寸。

每个尺寸检查页面水平溢出、可操作控件是否越界、项目工作区宽度、可见内容和浏览器控制台 warning/error。

## 2. 发现与修复

### 项目工作区宽度被通用 Sheet 样式覆盖

项目详情传入了 `sm:max-w-2xl`，但通用 Sheet 的 `data-side=right` 变体选择器优先级更高。修复前无论 800 或 1024 像素视口，工作区都只有 384 像素宽，无法合理承载文档、数据、实验、研究和发布等模块。

修复后使用与通用组件同作用域的响应式规则：

- 800×600：工作区宽 672 px；
- 1024×640：工作区宽 896 px；
- 1280×720：工作区宽 896 px，保留右侧工作区语义。

三个尺寸均没有页面水平溢出或越界的可操作控件。项目工作区的纵向内容仍需要滚动，这是当前单项目多模块布局的预期行为。

### 10 个控件缺少可访问名称

DOM 审计发现以下控件无法稳定被读屏或自动化按名称定位：

- 实验开始日期、实验结束日期；
- VOC 数据格式；
- 风险影响程度、风险发生概率；
- 依赖类型；
- 研究类型、关联研究计划；
- 洞察来源研究记录、洞察关联研究计划。

修复后全部具有明确中文 `aria-label`。新增组件回归测试会渲染六个项目面板，并逐项使用可访问名称查询这 10 个控件；同时锁定项目工作区三个响应式宽度类。

### 对话框键盘焦点证据不足

浏览器控制接口发送 Tab/Shift+Tab 时不会触发默认焦点移动，不能据此判断应用的焦点陷阱是否正常。为避免把工具限制误报为产品缺陷，新增 `@testing-library/user-event` 开发依赖和 `dialog-keyboard.test.tsx`，以真实键盘事件锁定以下行为：

- 首次引导打开后自动聚焦“暂时跳过”；
- Tab 按“暂时跳过”→“下一步”→“Close”移动，并在对话框内首尾循环；
- 项目 Sheet 自动聚焦首个输入框，Tab 到达保存按钮；
- Escape 关闭 Sheet，并把焦点恢复到打开按钮。

`user-event` 仅用于测试，不进入生产包；安装审计为 0 个漏洞。真实浏览器另行确认首次引导的初始焦点，以及 Escape 关闭后恢复到“重新打开首次引导”。
