# AI Product Manager Workspace

> 一个面向个人产品经理的本地优先工作台：把分散的项目资料、会议、需求、决策与风险，组织成可追溯、可确认、可导出的项目上下文。

![今日工作台](./assets/today-dashboard.png)

## 30 秒了解项目

产品经理同时推进多个 AI 项目时，真正困难的往往不是“再生成一份 PRD”，而是：信息散落在会议、文档和聊天里；结论缺少来源；AI 输出可能越权覆盖正式状态；隔一段时间后又要重新解释项目背景。

这个项目把解决方案收敛成三个原则：

1. **项目上下文优先**：在一个页面判断目标、需求、PRD、技术、开发、测试、风险、决策八类信息是已有、过期还是缺失。
2. **AI 只提案，人来确认**：AI 输出默认是草稿或候选，不能直接覆盖正式需求、决策和项目状态。
3. **本地优先且可追溯**：正式数据保存在本地 SQLite；来源、版本、项目边界和操作记录可以复核。

## 核心体验

```text
建立项目 → 导入/记录材料 → 形成正式知识 → 查看上下文缺口
        → 运行受限 Agent → 人工审核提案 → 导出/追溯版本
```

![项目上下文中心](./assets/project-context-center.png)

项目上下文中心不会用推断填补空白。缺少正式技术方案或测试报告时，它会明确显示“缺失”，即使存在相似候选材料也不会冒充事实。

## 已实现能力

- 今日驾驶舱、项目、里程碑、确认事项、提醒、归档与恢复
- 五类工作记录与知识库：会议、技术讨论、产品想法、AI 学习、项目决策
- 会议材料导入、稳定段落、检索、证据定位与安全删除
- 需求草稿、AI 候选、人工确认、不可覆盖版本与证据追溯
- 八类项目上下文聚合、缺口识别、来源下钻与 Markdown 导出
- 产品文档、设计 Brief、数据分析、VOC、竞品、风险、依赖、发布与复盘
- Windows Credential Manager、独立 Sidecar、结构化输出校验与脱敏 Trace
- SQLite 一致性备份、恢复前快照和只追加 migration

## 工程证据

| 维度 | 当前证据 |
|---|---|
| 技术栈 | Tauri 2、Rust、React 19、TypeScript、Vite、Tailwind CSS 4、shadcn/ui、SQLite |
| 代码结构 | 领域规则、Service、Repository、UI、Rust 原生命令、独立 Sidecar 分层 |
| 项目规模 | 236 个 `src` 文件、56 个领域模块、24 个 Service、46 个数据库 migration |
| 自动化 | 95 个测试文件；项目记录的最近一次完整预检为 306 项前端测试、17 项 Sidecar 测试、12 项 Agent Eval |

## 关键产品决策

- **从功能集合转向个人工作操作系统**：不继续堆独立面板，先统一知识契约和项目上下文入口。
- **候选材料不等于正式事实**：技术讨论可以成为技术方案候选，但不能自动让“技术方案”变成已完成。
- **AI 失败不影响基本工作**：没有 Provider 时，记录、项目、检索、确认、导出和备份仍可使用。
- **不做万能 Agent**：职责收口为产品分析、技术分析、项目管理、知识整理四类，并固定输入范围与输出 Schema。
- **不夸大桌面发布状态**：浏览器与自动化验收已有证据；NSIS、干净机、真实 Provider 和系统缩放仍是发布门禁。

## 当前状态

当前版本是 **作品集案例 v0.1.0**，展示的是已经运行的产品与经过记录的工程证据。完整源码仍在私有开发仓持续整理，尚未作为可下载的正式 Windows 产品发布。

公开源码前必须完成：

- 一个真实项目的八类上下文与来源下钻验收
- Windows 安装包、升级、卸载、凭据、Sidecar 与缩放的干净机验收
- 仓库元数据、许可证、敏感信息、演示数据和 Git 历史净化

实施顺序和逐条验收标准见 [MIMO.md](./MIMO.md)。
